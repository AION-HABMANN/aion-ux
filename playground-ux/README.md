# AION UX playground

> **Parked (2026-10-28).** Days 9 to 16 now run inside `../ux-lab` as their *original idea* (`/day/N/original/`), together with Days 1 to 8. This folder is kept for reference only; see `../ux-lab/README.md`, "The original idea of Days 9 to 16".

One Next.js project for the whole AION UX class (psychological UX and neuro-design, 16 days in 8 modules). It is built the way `../../aion-digital-learning/playground-dl` is built for Digital Learning, and follows `../UX-STANDARD.md`.

**Status (2026-10-25): Days 9 to 16 run in this project; Day 9 is upgraded (see below), Days 10 to 16 are moved as they were built. Days 1 to 8 are placeholders. Nothing is pushed; this folder is not a git repository of its own yet.**

## Run it

```bash
npm install
npm run dev          # http://localhost:3000 (runs build:css first)
npm run typecheck
npm run verify:course
npm run verify:day9   # Day 9 against the plan, its checks and its export
npm run build:css    # the per-day stylesheets (also runs before dev and build)
npm run build        # static export to out/
```

If `npm run dev` answers 500 with a message about `generateStaticParams` after you ran a build, delete `.next` and start again (a production build and the dev server use the same folder). The first compile of `/day/9/learn/[slug]` can log one "Failed to generate static paths" line in dev; the pages still serve and the production build is not affected.

## Stack

Next.js 14.2.35 (App Router), React 18.3.1, TypeScript, Tailwind 3, Zustand 5 (Day 9), React Router 6 (Day 15 only), three.js and model-viewer (Day 14 only), static export (`output: "export"`, `trailingSlash: true`, optional `NEXT_PUBLIC_BASE_PATH`). Next, React and the static-export setup match `playground-dl`; this was chosen by Claude on 2026-10-25 to keep the two projects on one stack and can be changed for all days at once.

Day 15 was a Vite app with a HashRouter. It is mounted client-side only (`components/day15/Day15Client.tsx`, `next/dynamic` with `ssr: false`) and its pages are reached as `/day/15/#/learn/foundations`.

## Why every day has its own stylesheet

The days were built with different Tailwind themes that clash on ten names (`ink`, `risk`, `warn`, `muted`, `hairline`, `card` radius and shadow, `sans`, `display`, `mono`), and Day 15 uses colour opacity (`bg-muted/25`) that cannot be kept if a colour is renamed to a CSS variable. Rather than renaming classes in five days, each day keeps its config and gets its own compiled CSS file, loaded only by its own root layout. Going between days is therefore a full page load. When a day is upgraded it moves into one shared theme and drops its file.

## Day 9 upgrade (2026-10-25)

Day 9 is the first day brought up to `../UX-STANDARD.md`:

- **The shape of a day (UX-STANDARD 2.8).** The navigation bar holds the day, `1 Analyse and decide`, `2 Decide` and `Extra`. The home (`/day/9/`) says what the day is about, gives the case that runs through it, shows the two routes with "You finish with: …", and lists what is in it for the learner (`data/day9/intro.ts`). **Route 1** (`/day/9/route-1/`, Levels 1 + 2) holds Materi A (the 8 concept cards of Levels 1 and 2), Tasks 1 to 3 and ends in the Activation Analysis File. **Route 2** (`/day/9/route-2/`, Level 3) holds Materi B (the 2 Level 3 cards), Task 4 and ends in the Activation Strategy Memo. Each route has a page map (a slim column on screens of 1280 px and up, a "Jump to" button below that) and its own export. **Extra** (`/day/9/extra/`) keeps what matches no plan item: the old start page (now `extra/studio-brief/`), the playground, progress and the inspector. The shape is data (`data/day9/routes.ts`), so the bar, the home and `verify:day9` read the same truth.
- **The plan's questions are fields.** The four tasks (Aufgabe 1 SkillRise, Aufgabe 2 HealthJourney, Fallstudie MoveWell, Transferprojekt) are 23 numbered items in the plan's order, written close to the plan's words (`data/day9/tasks.ts`), each under its route. Text boxes grow with what is typed; a list is one point per line; category assignment is one box per category; the one fixed choice is the plan's (variant A, B or C). Each task links to its work surface (the interactive case, or the board brief for Task 4). Answers are saved on the device (`lib/day9/tasks-store.ts`, key `aion-ux-day9-tasks`).
- **Checks are completeness only** (`lib/day9/tasks-logic.ts`): an empty field, too few lines, an answer that is too short. A different choice is never "missing"; nothing is marked right or wrong. A list of what is missing links to the exact field (scroll, focus, flash).
- **Export, one per route:** "Download my answers" (one self-contained HTML file named `1-{name}-day9-l1l2-activation-analysis` or `2-{name}-day9-l3-activation-strategy`) and "Print or save as PDF", plus "Clear this route". Never disabled; unanswered items are printed as "not answered"; no model answer, key or score (`lib/day9/tasks-export.ts`).
- **framer-motion is gone from Day 9.** It was replaced by `lib/day9/motion-lite.tsx`, a small stand-in built on the browser's Web Animations API (no dependency): enter, exit, `AnimatePresence`, in-view, keyframes, layout slides, SVG path and number tweens; the gauge needle is now plain CSS. `recharts` was never imported anywhere, so it was only removed from `package.json`. `framer-motion` stays installed for Day 15 until that day is upgraded.
- **Support under every question (DL-STANDARD 2).** "How to build the answer" (collapsed, 23 entries), plain-words glossary (18 terms, the first use of each in a task text is a button that opens a one-line explanation), and, behind the **mentor bar** (a quiet line above the navigation: passcode, "Fill all model answers", "Jump to this route's export", "Clear this route", "Lock"), a model answer for every field. The key is `data/day9/support.ts`; Task 3 is the plan's own Musterlösung, Tasks 1, 2 and 4 are **drafts** written from the case facts (the mentor panel says so). The key is never exported and, like the passcode, readable in the page's JavaScript: a convenience gate, not security (CLAUDE.md #7).
- **Accessibility pass, automated (CLAUDE.md #49).** axe-core 4.14 with the WCAG 2.0/2.1/2.2 A and AA tags, run in the browser on all 16 Day 9 pages and on Route 1 with every help, model answer and glossary note open: **0 violations**. Fixed on the way: four accent colours used as text now have darker `-text` tokens (`--risk-text`, `--inspect-text`, `--activation-text`, `--integrity-text`, 4.5:1 or better on the light surfaces; the originals stay for fills and for the dark console), a radio group that was a list, a map of links marked as an image, link names that did not contain their visible number, progress rings without a name, and "locked" shown by fading text. To repeat it: serve `node_modules/axe-core/axe.min.js` to the page, run `axe.run(document, { runOnly: { type: 'tag', values: ['wcag2a','wcag2aa','wcag21a','wcag21aa','wcag22aa'] } })`; do not commit a copy into `public/` (`verify:course` refuses it). Not done: a keyboard-only pass, zoom to 200 % and 400 %, one screen-reader pass; axe finds only part of the problems.
- **What is still missing against the Digital Learning standard** is listed, requirement by requirement, in `../docs/DAY9-VS-DL-STANDARD.md`.
- **`npm run verify:day9`** checks the tasks against the plan (4 tasks, 5 + 5 + 6 + 7 items, the plan's categories and counts, case names against `data/course.ts`), the completeness logic (including that a different choice is never missing), the export (escaping, "not answered", no keys), the shape of the day (two routes holding each task once, every Materi card in exactly one route, the home's "in it for you" items mapped to a route and the last one naming both documents, Extra links that resolve, exactly four entries in the navigation bar, a page map and a per-route export), the per-route file names, and that framer-motion and recharts are not imported.

**Materi is simple by default (UX-STANDARD 2.10) and sits on the route page as a path (2.11).** The route page opens with "Your path · 11 steps" (all the Core cards, then all the tasks, then the export); every card and task says "Step n of 11". A card is closed at first and shows its plain words; its button opens the demo, the check and "you can now" in place, and the optional self-check (never counted), the story, core idea, mechanism, balance and serious-domain parts are folded (one "Show every extra explanation" button opens all). A card is read when the reader presses "Mark as read". Old `/day/9/learn/<slug>/` addresses redirect to the card. Every card, task, stage and the route show their minutes (draft estimates in `data/day9/materi.ts`), every task block and the export carry a live "still missing" notice, and each card opens with its plain words and "Why it matters". The Materi prints no price or budget (effort is time and people, with a reason; `verify:day9` scans for price words). The audit against DL's 62 rules is `../docs/DAY9-AUDIT-62-RULES.md`. Cards are Core when a task of their route draws on them, Optional (folded on the route page) when none does; tasks list "Draws on" links and cards "Used in Task N". Data: `data/day9/materi.ts`; `verify:day9` checks it.

Not done for Day 9: example answers on another company, guided tables, the glossary inside the Materi card bodies, a case gap audit, the facilitator card, a person's keyboard, zoom and screen-reader pass, Word documents, EN | DE (English only, decided), and a shared store and palette with the other days. `canvas-confetti` is still used on the capstone page. See `../docs/DAY9-VS-DL-STANDARD.md`.

## Add the next day (Day 1 to 8, or a day being upgraded)

1. Mark the day `built: true` in `data/course.ts`.
2. Create `app/day/N/` (with `page.tsx`), `components/dayN/`, `data/dayN/`, `lib/dayN/`.
3. Use `@/components/dayN/...`, `@/data/dayN/...`, `@/lib/dayN/...` for imports; links start with `/day/N/`.
4. A page with a dynamic segment exports `generateStaticParams` from a server component and renders a client component (see `app/day/9/learn/[slug]/page.tsx`).
5. `npm run verify:course`, `npm run typecheck`, `npm run build`.
